# A/B 테스트 계획: 물음 답에 근거 줄을 붙일까 (2026-11-03)

시작하기 전에 정해 두는 기준. 판정은 정한 수를 다 모은 뒤 한 번만 한다(중간에 p값을 들여다보며 멈추지 않는다).

## 가를 의견
- A (`prod-a`): `butler-answer` 버전 3. 답 끝에 근거 줄을 붙인다.
- B (`prod-b`): 버전 3에서 한 줄만 바꾼 버전 4. 근거 줄 없이 한 문장.
- 두 버전 모두 데이터셋 실험(`butler-answer-reply`)을 먼저 통과해야 한다. 쓰기 지시문(`butler-write`)은 나누지 않는다.

## 나누기와 기록
- `AB_TEST=on` 일 때만. 별명을 해시해 0~99, 50 미만은 A, 나머지는 B(같은 사람은 늘 같은 버전).
- 트레이스 metadata `ab_variant`, `write` generation 에 프롬프트 버전 연결. 못 가져오면 production 버전.

## 판정 기준
| 항목 | 값 |
|---|---|
| 주 지표 | 반응 중 별로예요 비율(`user-feedback` = 0 + `report`) |
| 지금 비율 | 36% (11/02 실습: 반응 25개 중 별로예요 9개) |
| 의미 있다고 볼 최소 차이 | 10%p (36% → 26%) |
| 유의수준 / 검정력 | 5% / 80% |
| 그룹마다 모을 반응 수 | **335개** |
| 함께 볼 지표 | 답 지연 시간, 입력·출력 토큰(근거 줄이 빠지면 짧아짐), 수치 확인 WARNING 비율 |
| 내보내기 | B가 유의하게 낮고 함께 볼 지표가 크게 나빠지지 않으면 B 에 production, prod-a/prod-b 떼고 AB_TEST=off |

## 기간 계산과 결론
| 트래픽 | B 에 쌓이는 반응 | 10%p 를 가리는 데 |
|---|---|---|
| 11/02 같은 집중 시험일(하루 43건, 반응 58%) | 하루 12.5개 | 약 27일 |
| 평소(하루 10건, 반응 20%) | 하루 1개 | 약 335일 |
| 기관 전체가 쓴다면(하루 3,000건, 반응 10%) | 하루 150개 | 약 3일 |

- 5%p(36% → 31%)를 가리려면 그룹마다 1,398개, 집중 시험일 기준으로도 약 112일.
- 예: 일주일 돌려 A 9/25(36%), B 5/24(21%)가 나와도 p = 0.24 로 우연과 구별할 수 없다.
- 팀원이 6명이라 별명으로 나누면 한 그룹에 2~4명. 결과가 버전 차이인지 사람 차이인지도 가를 수 없다.

**→ 지금 실습 서비스에서는 A/B 테스트로 판단하지 않는다.** 분배와 기록이 되는지만 연습으로 확인하고,
"근거 줄이 필요한가"는 판정 기준을 구체적으로 써서(예: "답에 근거가 된 자료 줄을 인용한다") 데이터셋 실험으로 가르거나 팀원에게 직접 묻는다.
A/B 테스트는 새 버전이 크게 나빠지지 않았는지 지켜보는 용도로만 쓴다.
