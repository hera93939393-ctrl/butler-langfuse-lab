## 바꿀 구조
- 지금: `number-guard` 가 자료에 없는 숫자를 찾으면 WARNING 만 남기고 답은 그대로 나감. 한글 숫자는 못 읽음.
- 바꾼 뒤: `number-guard` 가 한글 숫자도 읽고, 자료에 없는 숫자가 있으면 **한 번 다시 쓰게** 함
  ("다음 숫자는 자료에 없다: 420, 170 … 자료 숫자 그대로 다시 써라"). 다시 써도 남으면 지금처럼 경고 배지.
- 모델에게 맡길 것: 요청을 이해하고 개조식으로 쓰기. 코드가 할 것: 답의 숫자를 자료와 대조, 다시 쓰기 요청.

## 코드와 맞춰 본 결과
- 처음 어긋난 단계: `app/pipeline.py` `run()` 의 ③ 쓰기(`llm.complete`), 트레이스 `write` generation.
  입력(지시문 + [요청] + [자료])과 출력, 모델, 토큰, 프롬프트 이름·버전이 모두 남음 → 계측은 고칠 것 없음.
- 고정할 앞 단계 결과: `steps.find_sources()` 의 반환값(`chunks`)이 그대로 `find-sources` 출력에 남고,
  데이터셋 항목 `input.chunks` 로 이미 쓰고 있음. 글로 이은 것은 `pipeline.list_sources(chunks)` → `input.sources`.
- 프롬프트 위치: Langfuse `butler-write`(staging=버전 3, production=버전 1), 코드 기본값은 `pipeline.WRITE_RULES`.
  변수 `{{request}}`, `{{sources}}`, `{{today}}`. 이번 수정은 프롬프트가 아니라 코드라 새 버전은 만들지 않음.
- 다시 쓰기 단계는 새 관찰 단위 `write-retry`(generation)로 남김. 기존 이름(`write-turn`, `read-request`,
  `find-sources`, `write`, `number-guard`)은 바꾸지 않음(AGENTS.md).
- 근거: langfuse 5.0.4 — `start_observation(as_type="generation", prompt=…)`, `create_dataset_item(id=…)` upsert,
  `run_experiment(evaluators=…)`, `create_score(data_type="BOOLEAN")`.

## 실제 AI 한글집사(본체)에 옮길 때
같은 순서를 쓰되, 원칙 0(실제 자료는 밖으로 나가지 않음)에 따라 기록은 Langfuse 가 아니라 본체의 SQLite 로그에서 읽는다.
데이터셋·코드 채점·전후 비교는 로컬에서 같은 방식으로 돌리고, LLM 심사와 Langfuse 화면은 쓰지 않는다.
